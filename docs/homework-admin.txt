Отчёт о тестировании сервиса TDlend
Проверки выполнены с помощью ИИ-ассистента в реальном Chrome, в независимых браузерных сессиях клиента, второго клиента и администратора. Результаты ниже получены на работающем локальном сервисе, данные вымышленные.

1. Три сценария проверки
• Доступ к админ-панели: обычный клиент вручную открывает административный адрес. Ожидается отказ сервера, а не просто отсутствие ссылки в меню.
• Конфликт слота: два клиента заранее выбирают одну услугу, одного мастера, дату и время, затем подтверждают по очереди. Ожидается одна созданная запись; второй получает отказ, список времени обновляется.
• Отмена администратором: администратор отменяет действующую запись. Ожидается сохранение записи со статусом отмены, освобождение времени и понятное уведомление владельцу.

2. Проверка доступа к админ-панели
Под новым клиентом «Мирон Кедровый» открыт адрес /admin напрямую, не через меню.
На экране дословно: «Доступ только для администратора», ниже ссылка «Войти».
Сервер вернул HTTP 403. Это установленный по ответу HTTP отказ, а не пустая страница и не только клиентское скрытие раздела. Административная таблица не открылась. Доступ закрыт на сервере.

3. Проверка записи двух клиентов на один слот
Первый клиент — «Демо-клиент», второй — «Мирон Кедровый», email miron.qa.28b76545@example.test.
Выбран слот 2026-11-12, 10:00, мастер Мария Волкова, услуга «Стрижка» длительностью 60 минут и ценой 1 800 ₽.
В обеих независимых сессиях слот выбран до подтверждения. Первый клиент подтвердил запись — сервер вернул HTTP 201, появилась запись № 2 и сообщение «Запись создана. До встречи в студии!».
После этого второй клиент нажал «Подтвердить запись». Дословный ответ на экране: «Это время уже занято или недоступно». Ответ API — HTTP 409.
Список времени перечитан, кнопка 10:00 из доступного времени исчезла. Второй записи на этот интервал не создано. Таким образом, устаревший выбор во втором окне не позволил занять уже забронированное время.

4. Проверка отмены записи
В отдельной сессии администратора найдена запись № 2 и установлен статус cancelled через форму статуса. На экране администратора появилось «Изменения сохранены.».
После обновления кабинета первого клиента запись сохранилась: 2026-11-12, 10:00, «Стрижка», Мария Волкова, 1 800 ₽. Вместо активного статуса появилась пометка «Отменена», кнопки отмены у этой записи больше нет.
Счётчик уведомлений изменился с 0 на 1.
Дословный текст уведомления: «Запись «Стрижка» на 2026-11-12 10:00 отменена администратором.»
Текст понятен: указаны действие, услуга, дата и время; это не общая фраза «Запись изменена». Проверена именно запись с мастером Марией Волковой, а не другая запись демонстрационного клиента.

5. Разбор поломки
Все три сценария прошли. Ниже гипотетический разбор конфликта, не выдуманное сообщение об обнаруженном дефекте.
Что было бы видно: второй клиент получил бы подтверждение, и два клиента увидели бы одну дату, время и мастера в своих кабинетах.
Причину нужно установить чтением обеих записей и серверной проверки интервалов: отключённая кнопка в одном браузере сама по себе не защищает от другого браузера. Особенно важно проверять всю длительность услуги, а не только совпадение минут начала.
Исправление: серверная проверка занятости в транзакции, с сохранением защиты при конкурентных запросах; отказ 409 выводится пользователю, после него перечитываются свободные слоты.
Повторная проверка: снова заранее выбрать общий интервал в двух независимых сессиях и подтвердить по очереди. Фактически проведённый сценарий дал именно требуемый результат: первая запись создана, второй клиент получил дословный отказ, 10:00 стало недоступно.
