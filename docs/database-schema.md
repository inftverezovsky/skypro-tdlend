# Схема данных

SQLite: `data/tdlend.sqlite` по умолчанию. Начальная схема: `migrations/001-initial.sql`. Совместимые дополнения колонок выполняются при открытии базы в `lib/database.mjs`; миграция и схема применяются при запуске сервера.

| Таблица | Назначение и связи |
|---|---|
| users | Уникальный email, имя, scrypt-хеш пароля, серверная роль client/admin |
| sessions | SHA-256 случайного токена, ссылка на users, срок действия |
| services | Название, описание, длительность, текущая цена, признак активности |
| masters | Имя, специализация, признак активности |
| schedules | Недельный график мастера: день недели и границы рабочего интервала |
| bookings | Владелец, услуга, мастер, дата/время, интервал в минутах, зафиксированная цена и статус |
| blocks | Недоступные интервалы конкретного мастера на дату |
| notifications | Владелец, текст, признак прочтения |

## Сохранение истории

Услуги и мастера отключаются, а не удаляются. Ранее созданная запись продолжает ссылаться на существующую строку. Цена копируется в запись при её создании и не пересчитывается после изменения прайса. Отмена меняет статус на cancelled; перенос изменяет существующую запись с сохранением id.

## Защита занятости

Частичный уникальный индекс запрещает одинаковое начало активных записей мастера. Триггеры дополнительно запрещают пересечение любых активных интервалов, в том числе с разным временем начала. API проверяет рабочий график, длительность, дату, активность услуги/мастера и блокировки. Проверка и сохранение записи выполняются в транзакции.

## Приватные данные

Файл SQLite, локальные сессионные токены и `demo-access.json` не публикуются. Случайный токен передаётся браузеру HttpOnly-cookie; в базе хранится только его хеш. При размещении в контейнере необходим постоянный том `/app/data`.
