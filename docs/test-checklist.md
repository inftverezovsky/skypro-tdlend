# Чек-лист приёмки

Этот файл задаёт сценарии, а не утверждает, что они пройдены. Фактические результаты, даты и дословные сообщения записываются в отчётах после выполнения.

## Клиент
- Гость открывает каталог: услуги, цены и длительность приходят из API.
- В базе меняется название одной услуги на уникальную метку; после обновления браузера видна метка, после восстановления — исходное название.
- Регистрация создаёт обычного клиента, даже если в запрос добавлена роль администратора.
- Неверный пароль даёт отказ API и понятный дословный текст на форме.
- Успешный вход сохраняется при обновлении и переходе между страницами; logout отзывает сессию.
- Новый клиент видит пустой кабинет, другой клиент — только собственные записи.
- Услуга → мастер → дата → свободное время → подтверждение создаёт постоянную запись, видимую после обновления.
- Слот учитывает длительность услуги, конец смены, уже занятые интервалы и блокировки.
- Отмена клиентом сохраняет запись со статусом cancelled и освобождает интервал.

## Негативные сценарии и разграничение прав
- Клиент вручную открывает админку. Ожидание: данные и команды закрыты сервером, виден понятный отказ.
- Клиент запрашивает чужую запись по id и пробует её отменить. Ожидание: отказ без выдачи чужих данных и без изменения записи.
- Два клиента в независимых браузерных сессиях заранее выбирают один слот. После подтверждения первым второй получает отказ; время обновляется. Сохраняется только одна активная запись.
- Длинная услуга пересекается с короткой, начатой позже. Ожидание: отказ, даже если время начала разное.
- Некорректная дата, прошлое время, несуществующие id, чрезмерный JSON и чужой Origin отвергаются сервером.

## Администратор
- Администратор видит общую таблицу записей; клиент не видит административную ссылку.
- Отмена сохраняет запись и освобождает время; клиент после обновления видит отмену и уведомление с услугой, датой и временем.
- Счётчик непрочитанных увеличивается после действия администратора и обнуляется после прочтения.
- Перенос сохраняет id записи, освобождает прежний интервал и проверяет новый.
- Изменение цены услуги не меняет сохранённую цену старой записи.
- Отключённые услуги и мастера не предлагаются для новой записи; прежние записи не исчезают.
- Блокировка интервала исключает пересекающиеся слоты; работа вне смены не предлагается.

## Адаптивность и публикация
- На 390 px нет горизонтальной прокрутки; все основные действия доступны и формы подписаны.
- На desktop нет ошибок приложения в консоли; пустые, загрузочные и ошибочные состояния читаемы.
- После перезапуска процесса база и записи сохраняются.
- До публикации проверено отсутствие базы, .env, паролей, ключей и приватных материалов курса в git.
- Публичный деплой проверяется отдельно: HTTPS, перенаправление HTTP, постоянное хранилище, время в кабинете и админке, отказ клиенту в доступе к админке.
- Внешний вход проверяется только после реальной настройки OAuth. Отсутствие настройки не считается успешным входом.
