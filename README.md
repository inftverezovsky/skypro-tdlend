# TDlend

Учебный сервис записи в студию ухода. Создан с помощью ИИ-ассистента для практики fullstack-разработки и проверки реального поведения в браузере.

## Стек
- Node.js 26 и встроенный HTTP-сервер.
- Постоянная база SQLite (`node:sqlite`).
- HTML, CSS, JavaScript ES modules; без сборщика и runtime npm-зависимостей.
- Cookie-сессии HttpOnly и salted scrypt-хеши паролей.

## Запуск

```bash
npm start
```

Локальный адрес по умолчанию: `http://127.0.0.1:3187`.
База и локальные данные создаются в `data/`, не входят в репозиторий. Учётные данные начального демонстрационного клиента и администратора генерируются локально; не публикуйте их в задачах, отчётах и видео.

```bash
npm test
```

Автоматические тесты проверяют HTTP API, права, хранение данных, конфликты интервалов и логику интерфейса. Они не заменяют визуальную проверку приложения.

## Возможности
Каталог услуг, регистрация и вход, выбор мастера и свободного времени, личный кабинет, отмена записи. Административные операции закрыты проверкой роли на сервере: записи, услуги, мастера и блокировки времени. Изменения со стороны администратора отражаются уведомлениями.

Список реализованных функций и ограничения нужно сверять с фактическими результатами тестов, а не только с этим описанием.

## Структура

- `server.mjs`, `lib/` — сервер, API, база, авторизация, расписание.
- `public/` — клиентский интерфейс и админ-панель.
- `tests/` — исполняемые тесты.
- `docs/` — дневник сборки, чек-лист, отчёты.
- `AGENTS.md` — паспорт проекта и ограничения.

## Учебные данные
Все услуги, имена мастеров и клиентские аккаунты в демонстрации вымышленные. На главной странице размещено предупреждение об учебном режиме. Не вводите настоящие персональные данные и пароли от других сервисов.

Внешний вход, отправка писем, платёжные системы и SMS не считаются подключёнными. Публичный адрес и работа через HTTPS требуют отдельного деплоя и приёмки; наличие GitHub-репозитория само по себе не является деплоем.

## Безопасность публикации
Не добавляйте `data/`, файлы SQLite, `.env`, локальные пароли, API-ключи и материалы личного кабинета курса. Для контейнера необходим постоянный том для базы. Перед доступом извне нужны HTTPS, защищённые cookie, корректный origin и проверка конфигурации.
